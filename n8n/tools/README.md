# n8n build and test harness

Builds `../sth-workflow-v1..v8*.json` from `live.json` (export of the live workflow, credential ids only) plus the code in `src/`. Run from this folder.

- `node build.js`: writes `sth-workflow-v1..v8-*.json` here (ignored by git) and `gen/*.lib.js` (the `Studio - Validate` library the unit tests load). v1..v7 must stay byte-identical to the committed files in `..` (v7 is the rollback copy of v8); v8 is the new one. `STH_OUT_DIR=<folder>` writes everything there instead (the extra-origin test builds into a temp folder).
- `node validate.js`: structure, credentials, secrets, diff against live, per-version rules (v7: settings, fallback output, no retry on job calls, expiries; v8: exactly 14 new and 9 changed nodes, every Renew path ends in a Respond node, the alarms come after the answer, claim / ack Lua embedded verbatim, nothing deletes `auth:ep`).
- `node tests/t-*.js`: unit tests (Code nodes in an n8n-like sandbox, Lua on a real Redis). Needs `redis-server --port 6391`; `t-v7.js` is the v7 suite; `t-auth.js` (sign-in claims v2, every renewal rule and refusal, the epoch normaliser, the breaker, the Redis scripts) and `t-v8.js` (hello v 8, `claim`, `collected` after `ack`, `result` 409, the extra-origin build) are the v8 suites.
- `e2e/`: suites against a local n8n 2.29.7 with mocked Upstash, Gemini and DNS. Setup once: `mkdir n8nrun && cd n8nrun && npm i n8n@2.29.7 --legacy-peer-deps`; `redis-server --port 6390`; `127.0.0.1 a.pub.test` in the hosts file; `node e2e/mock.js`. `e2e/reload.sh v7-bundle` imports a test copy and starts n8n.
- `./run-all.sh`: build, validate, every suite for v1..v8, then copies `sth-workflow-v8-bundle.json` to `..` (v7 must be byte-identical to the committed copy, it is not copied). `e2e/run-renew.js` is the v8 end-to-end suite (renew path on a real n8n: algorithm confusion, tampered and expired tokens, the cap, the epoch, fail closed, the breaker, the alarms, claim / collected on real Redis; `extra` = the extra-origin build). `WF_V8=1` switches the few e2e expectations v8 changes on purpose (hello 8, claims v2, the sign-in script has a third key). `WF_V7=1` (with `WF_V6=1`) switches the few v6 expectations that v7 changes on purpose (15 sources, ten hello modes, J4 meter factor 8.33).
- Regenerate `live.json`: n8n > the live workflow > Download, save here; check it holds no secret (`grep -iE "AIza|ya29|secret|token"` must show code only).
- All keys, tokens and secrets in `tests/` and `e2e/` are fixed fake test values.
- `STH_EXTRA_ORIGIN=https://<domain> node build.js` adds a second allowed app origin as a FINAL step (`applyExtraOrigin`) over every webhook node of each shipped bundle after it is built: the four webhooks of the v7 bundle and the five of v8 (`Renew Endpoint` included); the build fails when the count is not exactly that, so a new webhook cannot be forgotten. Comma-separated `allowedOrigins`; unset = the single origin `https://jay-leigh.github.io`, bundles unchanged. Do not commit a bundle built with it unless the domain is real.
- New v7 sources: `src/job7-*`, `quota7-*`, `studio7*`, `j4-settle.js`, `route7-unknown.js`; the patching is `buildV7` in `build.js`.
- New v8 sources: `src/auth.lib.js` (the one library of sign-in claims, `normEp`, `renewPrepare`, `renewDecide`; inlined into `Auth Evaluate`, `Auth Build Claims`, `Renew Prepare`, `Renew Evaluate`, and required by `tests/lib/fake-n8n.js`), `auth8-*.js`, `renew8-*.js`, `job8-*`, `job-claim*`; the patching is `buildV8` in `build.js`.
